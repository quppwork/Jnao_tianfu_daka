# 首页引导 Agent 升级需求报告

> 日期：2026-07-29  
> 范围：`agents/guide`（张宇老师 / 大宇智能体）  
> 立场：**不以「简易版 Agent」为目的**；对照市面主流产品级 Agent 能力，结合本产品教练场景给出升级需求。  
> 现状基线：Guide 主线 A0～C 已收口（bootstrap / 情境对话 / actions / 只读 tools / DB 长期摘要 / 抽检）。

---

## 1. 背景与结论

### 1.1 背景

首页引导 Agent 已具备「进页开场 → 情境注入 → 只读查数 → 跳转按钮」闭环，并能对晋级/排课类问题做**规则模糊化**（避免泄露 Part、达标次数等内部逻辑）。  
近期真实对话中仍出现「套话式导流」（如仅强调去「今日训练」看进度、对「下一等级 / 方案怎么排」信息密度不足），暴露出运行时成熟度与产品预期之间的落差。

### 1.2 一句话结论

当前是**能读业务数据的教练壳**，尚不是**能持续理解学生、多步办事、可核对事实的教练 Agent**。  
升级目标不是堆更多闲聊能力，而是把 Guide 做到与主流 Agent 同级的**运行时质量**，同时守住本产品边界（不替排课引擎做决策、不讲解晋级公式）。

## 2. 现状能力盘点（2026-07-29）

| 能力层 | 已有 | 主要缺口 |
|--------|------|----------|
| 人设与边界 | 张宇老师；先答后导；晋级/排课模糊化；导 QA / 训练 / 历史 / 报告 | 话术策略偏静态；复杂追问易退化为套话 |
| 情境 | 当日 situation + DB 长期摘要（streak / 弱项 / 时长众数） | 情境是静态卡片，非对话中生长的记忆 |
| 工具 | ~8 个只读工具；原生 FC → 启发式 → JSON 兜底 | **不能办事**；错字/语序易漏触发；补查仍偏规则 |
| 编排 | **多步只读 loop（2026-07-29）**：首轮 `plan_tools`，其后 `suggest_followup_picks` 按结果补查（轮次/累计上限，`tools_used.round`） | 尚非完整 ReAct（补查以规则为主，未每步再调 FC）；写操作未开 |
| 记忆 | 近 12 轮原文截断 + bootstrap 日缓存 | 无会话摘要；无偏好/未完成意图的结构化跨会话记忆 |
| 交接 | `handoff.navigate` 白名单按钮 | 仅跳转；**不携带任务上下文**进训练/答疑 |
| 交付形态 | 文本 + 单按钮 | 缺结构化卡片 / 可点选方案 / 依据展示 |
| 主动性 | 进页 bootstrap 一次 | 无掉队召回、周报、目标检视等主动节奏 |
| 评测 | fixture + live 抽检开关 | 缺日常 trace、工具命中率、掩饰不泄密专项回归 |

相关实现：`backend/app/agents/guide/*`、`shared/handoff.py`；约定见 `docs/数据闭环与预留说明.md` §1.6、`docs/前端后端API文档.md`「首页引导」。

## 3. 市面主流 Agent 对照（标尺说明）

对照对象为 ChatGPT / Claude / Cursor 类通用 Agent，以及客服 Copilot、Khanmigo / Duolingo Max 等**教育或任务型产品 Agent**——强调可交付任务与可运营质量，而非 Demo 级「能聊」。

| 主流能力 | 含义 | 本项目对照 |
|----------|------|------------|
| Agentic Loop | 观察→工具→看结果→再决策，直到完成或明确放弃 | 工具一轮定生死，再「说成话」 |
| 读写 + 人在回路 | 可执行写操作，危险动作需确认 | 刻意只读；参谋上限被锁死 |
| 长期记忆资产 | 摘要、偏好、未完成目标跨天续聊 | DB 统计强，**聊天记忆弱** |
| 可靠工具路由 | Schema/FC 为主，拒答与澄清 | FC + 关键词；缺工业级归一与二次规划 |
| Generative UI | 卡片、表格、对比、可点选 | 纯文本 + 跳转 |
| 主动节奏 | 提醒、周报、掉队召回 | 基本被动 |
| 可观测与评测 | Trace、成功率、红队话术集 | 有起点，未成体系 |
| 多模态 / 语音 | 图文语同一 Agent | Guide 以文本为主 |

**本项目相对优势（应保留）：** 业务真相源清晰（打卡、方案、天赋摘要）；人设边界清晰；Agent 间用 navigate 交接而非巨型 Orchestrator——方向正确，缺的是**载荷深度与运行时深度**。

## 4. 按项目实际结构：用户层 / 语义层 / 处理层

升级不按「再造一个通用 Agent」铺开，而按本仓库已有分层落点改。三条链路对应关系如下。

```text
用户层（前端体验与交接）
  vue_fronted/src/pages/index.vue
  userApi.js（guide bootstrap / chat / stream）
  跳转页：training / history / report / qa / talent …
        │  HTTP / SSE
        ▼
语义层（理解、边界、选工具、组话术）
  agents/guide/persona.py          人设与模糊化
  agents/guide/situations.py       当日情境判定
  agents/guide/tools/planner.py    意图→工具（FC/启发式）
  agents/shared/handoff.py         意图→navigate
  agents/guide/memory.py           会话截断 / bootstrap 缓存
  agents/guide/long_term.py        DB 长期摘要语义
  agents/guide/context.py          情境卡片注入文案
        │  runner 编排
        ▼
处理层（执行、落库、查数、流式出站）
  agents/guide/runner.py           tool-loop + 调模型
  agents/guide/tools/*.py          只读工具实现
  agents/guide/bootstrap.py        开场
  services/guide_service.py        会话 CRUD、调 runner、落库
  api/guide.py                     路由 / SSE
  （业务真相源）training / assessment / child_training_state …
```

### 4.1 用户层 — 要做什么处理

**落点：** `vue_fronted/src/pages/index.vue`、`utils/userApi.js`、以及 `openPage` 目标页（`training/index`、`training/history`、`report`、`qa` 等）。

| 处理项 | 现状 | 升级要做 | 对应需求 |
|--------|------|----------|----------|
| 对话呈现 | 文本气泡 + 思考中 + 流式 | 增加**结构化块**渲染（进度卡、今日项清单、弱项对比）；无数据时降级文本 | R6 |
| 操作按钮 | `actions[]` → `navigate` 单按钮 | 支持 **confirm 卡**（写操作二次确认）；多按钮/主次按钮 | R5 |
| 深交接 | `history?date=` 已有；其余多为裸跳转 | `query` / `handoff_payload` 带入训练/答疑/报告；对端可读可忽略并文档化 | R7 |
| 主动节奏 | 仅进页 bootstrap 欢迎 | 掉队/连续打卡/周简报的**进页主动一句**或入口提示（频控、可关） | R8 |
| 可核对 | 调试开关才看 `tools_used` | 可选「依据」折叠（非调试用户也可看到日期/技能来源摘要） | R3 |
| 会话体验 | 多会话列表已有 | 摘要标题、未完成意图标记（依赖语义层记忆） | R2 |
| 语音/多模态入口 | Guide 侧基本无 | 复用现有语音/选图能力接到同一会话（P2） | R11/R12 |

**用户层原则：** 不在前端重做意图识别；只消费 API 返回的 `reply` / `actions` /（新）`blocks` / `confirm` / `handoff`。

### 4.2 语义层 — 要做什么处理

**落点：** `persona` / `situations` / `planner` / `handoff` / `memory` / `long_term` / `context`（以及后续策略配置，若有）。

| 处理项 | 现状 | 升级要做 | 对应需求 |
|--------|------|----------|----------|
| 意图理解 | FC + 关键词启发式；错字易漏 | **查询归一**（同义、常见错序/错字）；FC 空则二次规划；少依赖裸子串 | R4 |
| 工具规划语义 | 每轮最多选工具一次，再生成 | 规划器支持「看结果再选下一步工具」的语义（与处理层 loop 配套） | R1 |
| 澄清策略 | 基本靠模型自由发挥 | 工具空/日期歧义/意图不清 → **强制先澄清一句**的人设与规则 | R3 |
| Grounding | 要求采信工具，仍会脑补 | 数字/日期/技能名必须绑定工具块；无工具则禁止报具体进度 | R3 |
| 边界与掩饰 | 人设已写晋级/排课模糊化 | 策略化（配置 + 红队集）；禁止把 Tier 公式说出口 | R9 相关 |
| 跳转意图 | `handoff.infer_navigate_intent` | 与工具结果、深交接载荷对齐（历史带 date、训练带关注技能） | R7 |
| 记忆语义 | 12 轮截断 + DB 统计摘要 | **会话滚动摘要** + 结构化「偏好 / 未完成意图 / 纠结点」；与 `long_term` 并列、不互相替代 | R2 |
| 情境文案 | `context.to_prompt_block` 静态卡 | 注入记忆摘要；档位等字段保持「勿解释晋级规则」标注 | R2 |
| 个性化策略 | 长 system prompt | 按天赋/弱项/situation 切换话术策略（配置，避免无限堆 prompt） | R10 |

**语义层原则：** 决定「听懂什么、能不能说、说什么边界、选哪类工具/跳转」；**不直接查库改库**（查改在处理层）。

### 4.3 处理层 — 要做什么处理

**落点：** `runner.py`、`tools/*`、`bootstrap.py`、`guide_service.py`、`api/guide.py`，以及只读真相源服务（`get_checkin_history`、`get_training_progress` 等）。

| 处理项 | 现状 | 升级要做 | 对应需求 |
|--------|------|----------|----------|
| 编排循环 | `_gather_tools` 一次 → `chat_completion(_stream)` | **多步 tool loop**（步数上限、超时、全程 `tools_used` 审计） | R1 |
| 工具执行 | `execute_tools` 同步只读 | 保持只读工具短输出；结果回灌给下一规划步 | R1 |
| 写操作 | 无 | 白名单写工具 + **确认票据**（未确认不落库）+ 审计日志；禁止改排课/Tier/代打卡 | R5 |
| 会话落库 | `guide_service` 存 role/content/meta | meta 扩展：`blocks`、`confirm`、摘要版本、记忆增量 | R2/R6/R5 |
| 长期统计 | `long_term.build_long_term_summary` | 保持 DB 聚合；不把内部连续达标计数暴露给话术 | 已有，守住 |
| API / SSE | `chat` / `chat/stream` 先 meta 再 token | stream 协议兼容新字段；确认/块可在 meta 或尾包下发 | R6/R5 |
| 主动触发 | 仅 bootstrap | 服务端判定掉队等条件，经 bootstrap 或独立轻量接口吐「主动一句」 | R8 |
| 可观测 | 日志 + 抽检 | trace（工具链、空工具率、耗时）；评测夹具扩展；**Guide 对话限流指标** | R9 / R13 |
| 鉴权 | 现有 session | 写工具与确认接口走同一鉴权；防越权 uid | R5 |
| Guide 对话限流 | 无用户级 QPS/日限额 | 短窗 + 日配额（内存→Redis）；429 | **R13** |

**处理层原则：** 唯一允许碰 DB/外部模型调用的执行层；语义层给出的规划在这里**跑完、记完、吐给用户层**。

### 4.4 三层协作（单轮升级后应长这样）

```text
用户层  输入话术 / 点确认 / 点跳转
   │
语义层  归一 → 意图/是否澄清 → 规划工具或确认写操作 → 人设边界
   │
处理层  loop：调工具 → 回灌 →（可选再规划）→ 生成 reply/blocks/actions
   │
语义层  校验 grounding / 掩饰 / 组装 handoff
   │
用户层  渲染文本+块+按钮；深跳转带 query
```

### 4.5 与需求编号对照（便于拆任务）

| 层 | 优先处理 | 需求 |
|----|----------|------|
| 处理层 | 多步 loop、审计、写操作闸门、SSE、**Guide 对话限流** | R1, R5, R9, **R13** |
| 语义层 | 归一/二次规划、澄清、grounding、记忆摘要语义、掩饰 | R2, R3, R4, R10 |
| 用户层 | 结构化块、确认卡、深交接、主动一句、可选依据、**429 友好提示** | R6, R7, R8, R11/R12, **R13** |

建议工程拆分也按层建 Issue（例如 `guide-user-ui-blocks`、`guide-semantic-normalize`、`guide-runtime-tool-loop`），避免前后端混在一个大 PR 里。

## 5. 升级需求（按优先级）

下列需求均为**产品级目标**，实施时可拆迭代，但验收标准不以「能演示」替代「可回归」。

### 5.1 P0 — 决定像不像真 Agent

#### R1. 多步 Tool Loop

- **需求：** 同轮对话内允许模型在步数上限内多次调用工具；每步可见上一工具结果；全程写入 `tools_used` 审计。  
- **动机：** 解决「先查档位再查今日方案再组织话术」等合理多跳；避免单次选错工具后无法补救。  
- **约束：** 步数上限、超时、禁止写库工具进入无确认路径（写能力见 P1）。  
- **验收：** 典型问句（进度 + 今日安排、天赋 + 今日状态）稳定走 ≥2 步工具且数字与工具块一致。

#### R2. 记忆升级（会话摘要 + 结构化学生资产）

- **需求：**  
  - 会话滚动摘要（超长历史压成摘要，而非仅截断 12 轮）；  
  - 结构化字段：偏好（如常用时长意向）、未完成意图、近期纠结点（与 `long_term` DB 统计并列，不互相替代）。  
- **动机：** 消除「老师不记得我昨天问过什么」；支撑跨天续聊。  
- **约束：** 不把晋级内部计数写入可对用户朗读的记忆；摘要需可审计、可清除。  
- **验收：** 跨会话追问「上次说的弱项」能引用结构化记忆或摘要，且不编造。

#### R3. 澄清与数字 Grounding

- **需求：** 工具空结果 / 多日歧义 / 意图不清时，优先一句澄清；回复中的日期、用时、字数、技能名必须可回溯到工具块。  
- **动机：** 减少「没有记录」误判与脑补档位/日期。  
- **验收：** 专项用例：今日无打卡问最近一次、模糊「数值」追问、工具失败时的话术。

#### R4. 工具路由鲁棒性

- **需求：** 查询归一（同义、常见错序/错字）；FC 返回空时的二次规划；降低对裸子串关键词的依赖。  
- **动机：** 生产口语与打字噪声下仍稳定触发正确工具。  
- **验收：** 错字/语序用例集命中率达标（具体阈值立项时定）。

### 5.2 P1 — 决定有没有教练产品力

#### R5. 受控写工具 + 确认卡

- **需求：** 少量高价值写操作（示例：记录「今日想练时长意向」、打开历史并定位某日、收藏「下次提醒弱项」）；必须二次确认 UI + 权限白名单 + 审计。  
- **动机：** 从「只能参谋」升级到「可代办一点事」，对齐主流 Agent，同时不放开排课写库。  
- **约束：** **禁止** Agent 直接改排课算法结果、改 Tier/连续达标、替用户提交打卡；写范围需产品书面圈定。  
- **验收：** 确认前不落库；拒绝越权工具名；有操作日志。

#### R6. Generative UI（结构化交付）

- **需求：** 与 `actions` 同级协议，支持进度摘要卡、今日项清单、弱项对比等可渲染块；前端按类型渲染，而非仅纯文本。  
- **动机：** 「下一等级 / 能练什么」类问题用结构化信息替代套话。  
- **验收：** 至少 2～3 种块类型端到端可用；无数据时降级为文本 + 澄清。

#### R7. 深交接（Handoff Payload）

- **需求：** 跳转训练 / 答疑 / 历史 / 报告时携带载荷（用户原话摘要、关注技能、目标日期、来源 session）。对端可选用，不强制改对端主流程。  
- **动机：** 跳转后仍延续「这一句问题」，而不是冷启动进空白页。  
- **验收：** 历史页已支持 `date` 定位；训练/答疑至少消费一种载荷字段或明确忽略并文档化。

#### R8. 主动节奏

- **需求：** 掉队召回、连续打卡鼓励、周简报（进页主动一句或消息通道，择一落地）。  
- **动机：** 教育教练品类中主动关怀接近标配。  
- **约束：** 话术仍遵守晋级/排课模糊化；不制造焦虑式催促。  
- **验收：** 触发条件可配置、可关闭；有频控。

#### R13. 每用户 Guide 对话 QPS / 日限额

- **需求：** 对首页引导对话接口（`POST /api/guide/chat`、`POST /api/guide/chat/stream`；若 bootstrap LLM 润色计入成本可一并）按 **用户维度** 限流：  
  - **短窗 QPS / 滑动窗口**（防连点、脚本刷）；  
  - **自然日（或训练日）配额**（控豆包费用与滥用）。  
- **落点：**  
  - 处理层：`api/guide.py`（或 `guide_service` 入口）复用 `app.core.rate_limit.check_rate_limit`；生产多 worker 升级为 **Redis** 桶（与生产已要求 `REDIS_URL` 对齐）。  
  - 用户层：`index.vue` 对 **HTTP 429** 展示友好文案（如「说太快了，稍等再问老师」），不整页崩溃。  
- **建议默认（立项可调，写入 env / `.env.example`）：**  
  - 短窗：每用户约 **10 次 / 60 秒**（chat + stream 合计）；  
  - 日限额：每用户约 **100～200 次 / 日**；  
  - 键示例：`guide:chat:{uid}`、`guide:chat:day:{uid}:{YYYY-MM-DD}`。  
- **动机：** 多步 loop 后单句仍约 1～2 次模型调用，但无用户级限额时刷对话会放大费用与超时；与语音接口已有限流对齐。  
- **约束：** 仅限 Guide 对话路径；不影响训练打卡、登录等；可用 env 关闭或放宽（压测/管理员）。  
- **验收：** 超短窗 / 超日限额均 429；单测覆盖桶计数；`运维与发版.md` 补充说明。

### 5.3 P2 — 决定能否长期演进

#### R9. 评测与可观测体系

- 意图→工具、掩饰不泄密、先答后导、数字 grounding 四类回归集；  
- 线上/预发 trace（工具链、耗时、空工具率）；  
- 红队话术（套取晋级规则、Part、达标次数）。

#### R10. 个性化策略层

- 按天赋标签 / 弱项 / 情境切换话术策略（配置化），避免把策略写死在超长 system prompt。

#### R11. 多模态入口（只读）

- 训练页/打卡相关截图解读，结果仍只读、可核对。

#### R12. 语音教练入口

- 复用现有语音能力，Guide 侧统一入口，不另起独立栈。
