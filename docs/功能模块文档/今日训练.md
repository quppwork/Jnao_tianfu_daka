## 一、系统定位

打卡系统是 JNAO 天赋成长平台的四大核心模块之一，承载用户"每日训练"功能。v2.0 重构后采用**多技能并行训练 + 独立 Tier 晋级**模型。

### 四大模块关系

```
┌──────────┬──────────┬──────────┬──────────┐
│ 天赋测试  │ 今日训练  │ 学科答疑  │ 成长里程碑 │
│  (测评)   │  (打卡)   │  (问答)   │  (追踪)   │
└──────────┴──────────┴──────────┴──────────┘
      ↑         ↑          ↑          ↑
      └─────────┴──────────┴──────────┘
                共用后端 API
                共用用户体系
```

## 二、v2.0 训练模型

### 2.1 技能分类

```
┌─────────────────────────────────────────────────┐
│              必修技能（5个）— 必须按序打卡            │
│  A. 超脑阅读  │  B. 影像追忆  │  C. 扫描速记        │
│  D. 极速运算  │  E. 极速学习                        │
├─────────────────────────────────────────────────┤
│              选修技能（3个）— 不阻塞后续              │
│  精力恢复(>8h弹窗) │ 多元感知(可打可不打) │ 高效作业(不打卡) │
└─────────────────────────────────────────────────┘
```

### 2.2 晋级机制

```
每个技能独立判定：
  打卡达标 → consecutive_pass += 1
  打卡不达标 → consecutive_pass = 0（严格连续，中断重置）
  consecutive_pass ≥ 3 → 技能 Tier + 1，计数重置

整体 Tier = min(所有活跃技能 Tier)  ← 最低原则
```

### 2.3 每日训练流程

```
用户选时长（20min / 40min / 1-2h / 2-3h / 3-4h / 4-5h）
  → Decision Tree 选策略 → 权重贪心填充必修 + 追加高效作业
  → 取各技能当前 OSS (stage,part) 对应音频
  → 生成有序 TrainingItem 列表
  → 用户按序打卡（必修严格顺序，选修不阻塞）
  → 打卡卡片 → per-skill 判定达标/Tier晋级/OSS推进
```

## 四、状态流转（🆕 v2.0）

### 4.1 单技能 Tier 晋级

```
超脑阅读 Tier 1:
  打卡: 用时 2.5min, 字数 900
  → 900/2.5 = 360字/分 < 267字/分(800字/3min)?
  等等: 800字/3分钟 = 267字/分钟
  900/2.5 = 360字/分钟 ≥ 267 ✓ 达标
  → consecutive_pass: 0→1

第2天: 达标 → consecutive_pass: 1→2
第3天: 达标 → consecutive_pass: 2→3 → 超脑阅读 Tier 1→2!
  → 达标标准升级为 Tier 2: 2000字/5分钟
  → consecutive_pass 重置为 0

第4天: 不达标 → consecutive_pass: 0→0（重置）
```

### 4.2 整体 Tier

```
超脑阅读 Tier=2, 影像追忆 Tier=1, 扫描速记 Tier=1
→ overall_tier = min(2, 1, 1) = 1
→ 排课仍用 Tier 1 公式
```

## 九、Part 轮换规则（🆕 v2.1）

### 9.1 定位

Part 轮换是**阶段（stage）内的音频循环逻辑**，与晋级体系互不干扰。

| 系统 | 驱动 | 变更 |
|------|------|------|
| **晋级体系** | 达标判定 → consecutive_pass → Tier+1 → `bump_oss_after_pass` | 推进 `oss_stage`（同时重置轮换计数器） |
| **Part 轮换**（本规则） | 打卡次数（达标/不达标都计） | 循环 `oss_part`，⚠️ **不改 stage** |

### 9.2 完整的打卡处理流程

每次打卡成功后，按以下顺序执行：

```
打卡提交
  │
  ├─ 1. 晋级体系 (process_checkin_progress)
  │     达标 → consecutive_pass +1
  │     bump_oss_after_pass → OSS 位置推进（stage/part）
  │     连续 3 次达标 → tier +1
  │        → advance_skill_tier
  │        → 重置 consecutive_pass = 0
  │        → 重置 part_listen_count = 0  ← 晋级归零
  │        → 重置 part_first_listen_at = None
  │
  └─ 2. Part 轮换 (_try_rotate_part_after_checkin)
         part_listen_count +1
         达到阈值 → 在当前 stage 内轮换 part
         ⚠️ 不改 stage
```

### 9.3 两条线路的关系

```
        晋级 (tier up)
            │
            ▼
     ┌──────────────┐
     │  新 stage     │ ← bump_oss_after_pass 推进
     │  新 part=1    │
     │  轮换计数器=0 │ ← advance_skill_tier 归零
     └──────────────┘
            │
            ▼
     ┌──────────────┐
     │  part 轮换    │ ← 在本 stage 内循环 part
     │  part+1/回1  │     不改 stage
     └──────────────┘
```

### 9.4 轮换触发阈值

每次**该技能**打卡成功后，`part_listen_count += 1`（达标/不达标都计），达到阈值则轮换。

| 用户类型 | 条件 | 阈值 |
|---------|------|------|
| **新学员** (`student_type="new"`) | 不限时间 | **5** 次打卡 |
| **老学员** (`student_type="returning"`) | 当前 part 首次打卡在 **≤7 天**内 | **20** 次打卡 |
| **老学员** (`student_type="returning"`) | 当前 part 首次打卡 **>7 天** | **14** 次打卡 |

7 天窗口看字段 `part_first_listen_at`（本 part **第一次计数**的时间），不是「训练日」日历。

**计数范围（2026-07-21）：** 仅对本次打卡涉及的必修技能计数（优先 `cards[].name`，否则当前项 `instructions.skill`）。不会一次打卡给全部五个必修技能各 +1。

**产品前提：** 学生一天一次训练；阈值按「该技能累计打卡次数」理解即可（新学员约 5 个训练日换一次 part，若每天都打该技能）。

### 9.5 轮换后去向

```
当前 stage 有下一个 part → oss_part += 1
当前 stage 无更多 part  → oss_part = 1（回到当前 stage 重新循环）
                        ⚠️ 不改 oss_stage
```

轮换后：`part_listen_count = 0`，并重新写入 `part_first_listen_at`（老学员 7 天窗口重新起算）。

### 9.6 晋级后归零

```
tier 提升时 (advance_skill_tier):
  → part_listen_count = 0      ← 重新计数
  → part_first_listen_at = None  ← 重新计时
```

**效果：** 进入新 stage / 新 Tier 后，轮换从头开始计数。

同一次打卡内顺序：先跑晋级体系（可达标推进 OSS），再跑 Part 轮换（对该技能 +1）。两条线独立，可能叠在同一次提交里。

### 9.7 新老学员身份转换

| 场景 | 方式 |
|------|------|
| 注册时自选 | Onboarding Step 1 选择「新学员」/「老学员」 |
| 自动转换 | 新学员累计 `TrainingRecord` ≥ 30 次 → `student_type=returning`（与是否已有 `completed_at` 无关） |
| 老学员注册初始化 | `build_state_from_onboarding()` 根据历史数据估算初始 tier/part |

### 9.8 存储字段

每个技能：

```json
{
  "影像追忆": {
    "part_listen_count": 0,
    "part_first_listen_at": null
  }
}
```

- `part_listen_count`：当前 part 已打卡次数  
- `part_first_listen_at`：本 part 首次计数时间（ISO）；首次 +1 时写入，轮换后重置为当前时间

| 职责 | 文件 | 函数 |
