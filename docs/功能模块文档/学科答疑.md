## 一、功能定位

AI 一对一学科辅导。现行主路径：**文字提问 + 拍照发题**，分科 chip（数学 / 语文 / 英语 / 科学），按天赋与学段注入策略。

核心体验：像跟老师聊题一样自然；引导「不会」时可少打字、多点选。

## 三、「不会」引导流程（产品设计）

用户不知如何提问时，用可点击引导降低门槛（实现细节随版本微调，原则不变）：

```
用户表达不会 / 空求助
  ↓
选学科（chip 或引导按钮）
  ↓
选题型或「说不清楚」
  ↓
拍照发题 / 文字描述题干
  ↓
进入正常问答
```

### 设计原则

- 尽量给可点击选项，允许零长文输入走到发题
- 「说不清楚」合法
- 拍照是兜底（`POST /api/qa/upload-image`）

后端另有弱澄清：首轮无图且寒暄/空求助时追问题干（见 API 文档 `clarified`）。

## 四、异常与安全（产品期望）

| 场景 | 期望处理 |
|------|---------|
| 空/过短输入 | 提示再说清楚或拍照 |
| 错选学科 | 后端 `subject_mismatch` + 建议学科，**不**自动改会话学科 |
| 说脏话 / 跑题 | 温和拉回题目 |
| 超纲 | 诚实说明能力边界 |
| 安全高危 | 预设话术，不自由发挥（与 Guide/评测约定对齐） |

具体话术以 `agents/qa` persona / clarify 实现为准。

## 六、技术方案（现行）

### 6.1 主链路

```
文字 / 图片 → POST /api/qa/chat 或 /chat/stream
  → 错频道检测、弱澄清、滚动摘要、教练 mistake_pattern
  → 分科 prompt + 豆包 LLM
  → 气泡展示（流式可选）
```

语音：通用 `POST /api/voice/asr` · `/api/voice/tts` 仍在语音服务文档中；**答疑页默认不启用**。

### 6.2 API（与实现对齐）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/qa/chat` | 文字对话（可带 `subject`、`image_id`） |
| POST | `/api/qa/chat/stream` | SSE 流式 |
| GET | `/api/qa/sessions` | 会话列表 |
| POST | `/api/qa/sessions` | 新建 |
| GET | `/api/qa/sessions/{id}` | 详情 + 消息 |
| DELETE | `/api/qa/sessions/{id}` | 删除 |
| POST | `/api/qa/upload-image` | 拍照/选图上传 |
| GET | `/api/qa/images/{id}` | 取图 |

限流与 Guide 类似（见 API 文档 env）。无单独 `POST /api/qa/clear`。

### 6.3 数据要点

- `qa_session`：`subject`、`meta_json.rolling_summary` 等  
- `qa_message`：`content`、可选图片；`voice_url` **预留未用**  
- 助手消息 `meta_json` 可持久化 `mistake_pattern`（供后续教练上下文）
