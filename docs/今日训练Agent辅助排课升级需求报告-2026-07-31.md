# 今日训练 Agent 辅助排课升级需求报告

> 日期：2026-07-31  
> 范围：`training_schedule_service` / `training_formula_engine` + 可选新建 `agents/training_schedule`（或 `services/training_agent_assist`）+ `vue_fronted/src/pages/training`  
> 立场：**B 方向 — Agent 辅助可选；规则引擎仍为默认真相源；失败/不选即回退规则**  
> 基线：排课 v3.0（Decision Tree + Strategy Pipeline + 权重贪心）已上线；Guide / QA Agent 另线；架构约定「核心调度不走 LLM」

---

## 1. 背景与结论

### 1.1 背景

今日训练方案生成当前完全由确定性引擎完成：

```text
选时长 → POST /api/training/schedule
      → populate_plan_items
      → expand_formula（Decision Tree + 权重）
      → OSS stage/part 取音频 → plan_items 落库
```

LLM 仅用于教练文案（`training_child_guide`）；`training_curriculum.yaml` 中 `llm_routing.enabled: false`，`usage: coach_text_only`。

产品希望探索：在**不推翻规则引擎**的前提下，增加一条「可走 Agent 生成训练方案」的辅助路径；用户不选或 Agent 失效时，仍走现有固定规则。

### 1.2 一句话结论

**可行且应做成「旁路辅助」而非「替换主引擎」。**  
Agent 只产出结构化草案（技能意图列表）；必须经**校验/投影层**落到合法槽位与 OSS 内容后才能落库；任何失败静默或明示回退到 `populate_plan_items` 规则路径。  
**禁止**用 Agent 直接改 Tier / OSS / 代打卡；**禁止** Guide.runner 直接写排课（与 Guide R5「禁止排课写」一致）。

### 1.3 已否决：A 方向（全量 Agent 排课）

| 原因 | 说明 |
|------|------|
| 硬约束多 | Tier、OSS stage/part、日切、已开始禁重排、晋级与打卡状态机必须确定 |
| 幻觉风险 | 编造技能、跳课、时长对不齐会导致不可评测的生产事故 |
| 与架构冲突 | `体系架构设计.md`：「核心调度不走 LLM」 |
| 运维成本 | 回归集、成本、延迟全面抬升 |

本报告只落地 **B**。

## 2. 现状能力盘点（2026-07-31）

| 能力域 | 已有 | 与 B 的关系 |
|--------|------|-------------|
| 规则排课 | `training_formula_engine` + `training_schedule_service.populate_plan_items` | **默认主路径，必须保留** |

## 3. 目标形态（用户可感知）

### 3.1 默认（不变）

用户选时长 → 一键生成 → **规则引擎**出方案（现状）。

### 3.2 可选辅助

在时长确认/生成区域增加明确入口（复用现有按钮区，**不新造整页流程**），例如：

- 「标准方案」（默认，规则）
- 「智能推荐」（Agent 辅助）

行为：

| 用户操作 | 系统行为 |
|----------|----------|
| 点标准方案 / 不碰智能 | `populate_plan_items` 规则路径；`schedule_mode=rule` |
| 点智能推荐且成功 | 草案 → 校验投影 → 落库；`schedule_mode=agent` |
| 智能推荐失败/超时/校验不过 | 自动回退规则生成；`schedule_mode=agent_fallback`；可 toast「已改用标准方案」 |
| 训练已开始 | 两条路径均禁止重生（沿用现有 403） |

文案需说清：**智能推荐仍受当前训练进度与课表约束，不是自由点菜。**

## 4. 分层设计：用户层 / 语义层 / 处理层

```text
用户层（训练页）
  选时长 +「标准方案」/「智能推荐」
  展示 schedule_mode；失败回退提示
        │
语义层（Agent 草案，可选）
  读：天赋摘要、overall_tier、弱项、近几天 skills、意向时长
  出：结构化 draft = [{ skill, role?, minutes? }, ...]
  禁止：直接写 DB、改 Tier/OSS
        │
处理层（校验投影 + 规则兜底）
  validate_and_project(draft) → 合法 slots + ContentItem
  失败 → populate_plan_items（规则）
  成功 → 写 plan_items（与规则路径同一落库形态）
  再 → build_coach_text_for_plan
```

### 4.1 用户层

| 项 | 要求 |
|----|------|
| 入口 | 训练页现有生成流程旁增加可选；Guide 仅可带 `from=guide&mode=agent` 暗示，**不在 Guide 内落库** |
| 加载态 | 智能路径可略长（建议超时 8～12s），超时即 fallback |
| 可关 | 全局开关关闭时隐藏「智能推荐」，避免死按钮 |

### 4.2 语义层（Agent）

| 项 | 要求 |
|----|------|
| 输入 | 时长、overall_tier、grade_band、skill_tiers、近史技能名、天赋类型；**不**注入晋级公式原文 |
| 输出 | 严格 JSON schema（技能名枚举 + 可选分钟）；拒绝自由文本当方案 |
| 模型 | 豆包（与现网一致）；prompt 强调「只能从给定技能列表选」 |
| 边界 | 不解释 Tier 公式；不承诺「跳级」「换课包」 |

建议落点（二选一，开工前定）：

- `backend/app/services/training_agent_assist.py`（薄，先服务层）  
- 或 `backend/app/agents/training_schedule/`（与 guide/qa 并列，但仍**禁止**与 guide/qa runner 互调）

### 4.3 处理层（必须，不可省）

校验/投影至少包括：

1. 技能名 ∈ 当前 Tier 可用必修/选修集合（curriculum）  
2. 每个技能能 `_find_content_for_skill`（当前 OSS stage/part 或 fallback）  
3. 槽位数 / 总时长相对 `planned_minutes` 在容差内（建议 ±15% 或按 slot_table 对齐）  
4. 不包含未知选修触发逻辑冲突项  
5. 方案未开始；日切窗口外按现有 `is_new_day_ready`  

投影策略（推荐）：

- Agent 给出技能顺序意图 → **用规则引擎的 slot 结构消化**（例如按意图重排/加权，再 greedy_fill），而不是把 LLM 分钟数原样当 duration  
- 若投影后有效项为 0 → 判定失败 → 全量规则 `expand_formula`

落库后形态与规则路径一致：`TrainingItem` + instructions.skill + content_item_id，避免两套播放/打卡协议。

## 5. API / 配置约定（草案）

### 5.1 排课请求扩展

`POST /api/training/schedule` 增加可选字段（名称可微调）：

```json
{
  "planned_minutes": 60,
  "schedule_prefer": "rule" | "agent"
}
```

| prefer | 行为 |
|--------|------|
| `rule` / 缺省 | 仅规则（现网） |
| `agent` | 先试 Agent；失败则规则；响应带最终 `schedule_mode` |

响应已有 `schedule_mode`，扩展取值：

| 值 | 含义 |
|----|------|
| `rule` | 规则生成 |
| `agent` | Agent 草案校验通过并落库 |
| `agent_fallback` | 用户要了 Agent，但回退规则 |
| `existing` | 沿用已有方案（未改时长等，现逻辑） |

### 5.2 开关

| 配置 | 说明 |
|------|------|
| `llm_routing` 扩展或 `TRAINING_AGENT_SCHEDULE=0/1` | 总开关；默认 **关** |
| 超时 / 日限额 | 防刷；可对齐 Guide 限流思路（更严亦可） |

YAML 建议演进（示意，非立刻改文件）：

```yaml
llm_routing:
  enabled: false
  provider: doubao
  usage: coach_text_only   # 现网
  # 升级后可增加：
  # schedule_assist: false
  # schedule_timeout_sec: 10
```

## 6. 需求清单（按优先级）

### P0 — MVP（可灰度）

| ID | 需求 | 验收要点 |
|----|------|----------|
| T0 | 总开关默认关；开后训练页出现「智能推荐」 | 关时 UI/API 与现网一致 |
| T1 | `schedule_prefer=agent` 路径：草案 → 校验投影 → 落库 | 项可播放、可打卡，与规则方案同协议 |
| T2 | 任意失败回退规则；`schedule_mode=agent_fallback` | 用户仍得到可用方案 |
| T3 | 已开始 / 日切 / 时长&lt;20 等与现网同一套拦截 | 无旁路绕过 |
| T4 | 结构化日志：prefer、最终 mode、失败原因码 | 可查「为何 fallback」 |

### P1 — 体验与质量

| ID | 需求 | 验收要点 |
|----|------|----------|
| T5 | fallback toast / 轻提示 | 不静默到让用户以为智能生效 |
| T6 | 小回归集：非法技能、空池、超时、已开始 | pytest fixture |
| T7 | 与近史软惩罚/弱项：prompt 注入摘要，不泄漏连续达标次数 | 对齐 Guide 模糊化原则 |
| T8 | 限流（用户日次数） | 超限直接走 rule 或 429 |

### P2 — 可选增强

| ID | 需求 | 说明 |
|----|------|------|
| T9 | Guide 深交接带 `mode=agent` | 训练页读取后预勾智能；仍在训练 API 生成 |
| T10 | 确认卡二次确认（类 Guide R5） | 仅当产品要「先预览再应用」时再做 |
| T11 | A/B 或后台统计 agent vs rule 完成率 | 运营向，非阻塞 MVP |

### 明确不做

- 用 Agent **替换** Decision Tree 作为唯一排课器  
- Agent 修改 Tier / consecutive_pass / OSS stage  
- Guide/QA runner 互调或超级 Orchestrator 统一排课  
- 已开始训练后允许 Agent「重排今日」

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Agent 常失败 → 按钮失去信任 | 严格超时；fallback 提示；监控 fallback 率，过高则默认关 |
| 校验过严 ≈ 永远 fallback | 投影策略偏「意图→规则填充」，而非逐字段照抄 LLM |
| 校验过松 → 坏方案进库 | 无 ContentItem 不得落项；总时长容差；单测锁边界 |
| 成本/延迟 | 开关 + 日限额；超时短；仅用户主动点才调用 |
| 与「不讲排课规则」话术冲突 | Agent/前端只说「按你当前进度推荐」，不展示公式 |
