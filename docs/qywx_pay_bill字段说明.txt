qywx_pay_bill（企微对外收款账单）字段说明
========================================
用途：企业微信「对外收款」流水入库后，再关联客户 / 收款员工。
区分原则：无前缀 = 付钱的客户；payee_* = 收钱的员工。

示例行（截图中 id=85，带退款单号）：
  id              = 85
  transaction_id  = 50300907962026072884243966786
  out_trade_no    = 178445127154000015f1146adcZv
  out_refund_no   = 178445127154000015f1146adcZv_1785228609_fRt...
  （同屏 id=79 且 out_refund_no 为空 → 正常收款，不是退款）


一、订单本体（企微收款接口）
--------------------------
序号              管理界面行号，不是数据库字段
id                本表自增主键
transaction_id    微信支付交易号（微信侧）
out_trade_no      商户订单号（业务/小鹅通侧下单号）
out_refund_no     商户退款单号；收款单多为空，退款单才有值
pay_time          支付/退款发生时间（DATETIME）
bill_type         账单类型：0=收款，1=退款
payment_type      支付方式（企微枚举）
trade_state       交易状态（企微枚举）
total_fee         收款金额（元，DECIMAL）
total_refund_fee  退款金额（元）；退款单重点看此字段
commodity         商品/项目说明
remark            备注
mch_id            商户号


二、员工侧（收款人 / 跟进员工，payee_*）
--------------------------------------
payee_userid      收款员工的企微 userid
payee_name        员工姓名（从 qywx_follow_user / 通讯录回填）
payee_mobile      员工手机号
payee_unionid     员工微信 UnionID
payee_third_uid   员工在 ys_third_party_user 的 uid
payee_xet_user_id 员工在 ys_xet_user_lists 的 user_id


三、客户侧（付款人，无 payee_ 前缀）
----------------------------------
external_userid   付款客户的企微外部联系人 ID
contact_name      账单自带联系人姓名（接口 contact_info.name；退款单接口常不返回，
                  同步时会用原收款单/微信昵称回填展示）
contact_phone     账单自带联系人手机（接口 contact_info.phone）
wx_name           客户微信昵称（客户详情回填；退款可从原收款单/同客户其它账单抄）
unionid           客户微信 UnionID（打通小程序/小鹅通）
third_uid         客户在 ys_third_party_user 的 uid
xet_user_id       客户在小鹅通的 user_id
bind_phone        客户在小鹅通绑定的手机号


四、同步元数据
--------------
raw_json          接口原始 JSON（排查用）
range_begin       本次拉取时间窗口起点
range_end         本次拉取时间窗口终点
fetched_at        本条写入/拉取时间


五、员工信息存在哪 / 会不会自动补
--------------------------------
员工主数据表：qywx_follow_user（姓名、手机、unionid、third、xet）
账单回填：每次同步 --apply 后，用员工表 JOIN 写 payee_*

通讯录手机号文件（服务器持久卷，有则自动读入员工表）：
  容器内：/app/data/qywx_export/qywx_follow_mobile.csv
  仓库：docs/export/qywx_follow_mobile.csv（pull 后 docker cp 进容器）

已在 qywx_follow_user 且有手机号的员工：
  → 新收款单出现同一 payee_userid 时，会自动补全 payee_*（无需再导 Excel）
通讯录换号后：更新上述 CSV，下次收款同步会覆盖员工表手机并回填账单。


六、相关定时任务（宝塔）
----------------------
定时脚本不用单独加「员工同步」；--apply 已含员工+payee 回填。

每 30 分钟（收款最新）：
  docker exec jnao-daka-backend python -u tools/sync_wework_pipeline.py \
    --recent-only --recent-days 1 --skip-served --skip-detail --apply

每天 04:00（近1天 + 收款往前补 + 历史详情连续补几小时）：
  docker exec jnao-daka-backend python -u tools/sync_wework_pipeline.py \
    --recent-days 1 --history-batch 800 --history-rounds 0 \
    --history-max-minutes 180 --pay-history-days 180 --apply
  # history-rounds 0 = 一直补到没有待同步；180 分钟到点会停，第二天继续

进度文件（容器内，勿删；读档续跑）：
  /app/data/qywx_export/.qywx_pipeline_state.json
  - synced_external_userids：客户详情已同步名单（历史只补未同步的）
  - pay_history_oldest_ts：收款历史已覆盖到的最早时间（已覆盖不再重拉）

说明：日志里「历史第 N 批」是客户详情，不是 pay_bill。
pay_bill 历史靠 --pay-history-days；若曾 APPLY 失败导致表空但读档已前进，
可临时加 --force-pay-history 重拉收款历史。
