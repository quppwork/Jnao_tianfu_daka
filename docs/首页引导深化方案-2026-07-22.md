## 一、背景与结论

### 1.1 现状（A0 后）

**开场（已升级）：**

```
进首页 → POST /api/guide/bootstrap
  → build_guide_context → resolve_situation → 模板/LLM 欢迎
  → 前端欢迎卡 + next_action 按钮
```

**对话（A1 已注入情境）：**

```
进首页聊 → runner.build_chat_system_prompt（人设 + 情境卡片）
  + 截断历史 → 豆包补全 → GuideMessage
```

关键实现：

| 模块 | 路径 | 说明 |
|------|------|------|
| API | `backend/app/api/guide.py` | session / **bootstrap** / chat / chat/stream / clear |
| 服务 | `backend/app/services/guide_service.py` | 会话持久化 + bootstrap 入口 |
| 人设 | `backend/app/agents/guide/persona.py` | **已解限制**：可读个人状态；禁解题/编造/改课 |
| 记忆 | `backend/app/agents/guide/memory.py` | 历史截断 + **按日开场缓存**（内存 + profile_json） |
| 情境 | `context.py` / `situations.py` / `bootstrap.py` | sense → decide → speak |
| 前端 | `vue_fronted/src/pages/index.vue` | Hero + 四宫格 + **动态欢迎卡** + 气泡对话 |
| 测试 | `tests/test_guide_bootstrap_a0.py` | 情境判定 + bootstrap API |

### 1.2 目标定位

把首页对话从「平台客服说明书」升级为 **认识这个孩子的教练开场**：

- 依据 **实时状态 + 打卡/测评史** 说话  
- 引导到正确入口（测评 / 今日训练 / 答疑）  
- **不**替代学科答疑讲题  
- **不**替代排课引擎写今日方案  

### 1.3 是否做成「小型 Agent」

分两档，避免一上来过度工程：

| 档 | 能力 | 是否算小型 Agent |
|----|------|:----------------:|
| A. 情境教练对话 | 注入学生卡片 + 进页开场 + 前端动作按钮 | 过渡形态（带上下文的聊天 + 固定流水线开场） |
| B. 只读 Guide Agent | 按需调工具查画像/今日计划/打卡时间线后再答 | **是**（感知 → 选工具 → 再答） |

**结论：朝小型 Agent 方向走。**  
首刀不做完整 tool-loop，先做 **固定三步开场流水线**（代码 sense/decide，LLM 可选 speak）——这是微型 agent，稳定且够用。

## 三、首刀设计：进首页触发开场 Agent（A0）

> 2026-07-23 确认：用户进入首页即触发简单 agent；按情况给不同欢迎语（模板保底，可选调 LLM）。

### 3.1 微型 Agent 流水线（固定三步，非开放 tool-loop）

```
进入首页
  → ① sense  build_guide_context(child_id)     // 代码查库
  → ② decide resolve_situation(context)       // 得到 situation + next_action
  → ③ speak  模板欢迎 或 LLM 润色（失败降级模板）
  → 返回 bootstrap 载荷 → 前端欢迎区展示
```

工具调用由代码固定执行，LLM **不**自行选工具——降低幻觉与成本，仍具备「感知 → 决策 → 表达」形态。

### 3.2 情境枚举 `situation`

| situation | 判定（示意） | 欢迎方向 | next_action |
|-----------|--------------|----------|-------------|
| `need_assessment` | 无有效天赋/测评 | 先去做天赋测试 | `talent` |
| `ready_to_train` | 有测评；今日无方案或未开始 | 可以开始今日训练 | `train` |
| `training_in_progress` | 今日有项且已开始未完成 | 继续今天的训练 | `train` |
| `training_done` | 今日已完成或必修打卡齐 | 肯定 + 可去答疑/成长 | `qa` 或 `growth` |
| `sparse_return` | 有测评且距上次打卡 ≥ N 天（建议 N=3） | 欢迎回来 + 建议开练 | `train` |

优先级建议：`need_assessment` > `training_done` / `training_in_progress` > `sparse_return`（可并入文案）> `ready_to_train`。  
具体阈值与「已开始」定义实现时与训练页 `_plan_has_started` / `day_locked` 对齐。

### 3.3 情境卡片 `build_guide_context`

结构化摘要（JSON 或短 Markdown，控制长度），字段建议：

| 字段 | 来源 |
|------|------|
| nickname / grade / talent | profile / assessment |
| has_assessment | 是否有效测评 |
| today_plan：存在与否、planned_minutes、item 数、完成数、是否已开始 | TrainingPlan + items |
| days_since_last_checkin | TrainingRecord 最近 train_date |
| skill_tiers 摘要（可选，可截断） | training_progress |
| situation / next_action | resolve_situation |

### 3.4 模板 vs LLM

| 方式 | 用途 |
|------|------|
| **按 situation 的模板句** | 必达保底；豆包未配置 / 超时 / 报错时使用 |
| **LLM 润色（可选开关）** | 输入：解限后人设 + 情境卡片 +「只写欢迎 2～4 句，点名下一步」；输出纯文本 |

推荐默认：`template_fallback + llm_polish`（有 key 则润色，否则模板）。

### 3.5 API：`POST /api/guide/bootstrap`

与 `GET /session` 分离：session 保持轻量读历史；开场可能调 LLM，需独立超时与缓存。

**请求：** 可无 body（鉴权取 `child_user_id`）；可选 `{ "force": false }` 强制刷新。

**响应（示意）：**

```json
{
  "training_day": "2026-07-23",
  "situation": "ready_to_train",
  "next_action": "train",
  "welcome": "……动态欢迎语……",
  "context_summary": { "...": "可选，调试用" },
  "source": "llm" | "template" | "cache"
}
```

### 3.6 缓存策略

| 项 | 约定 |
|----|------|
| Key | `child_user_id` + 训练日 `plan_date`（与训练日切一致，含凌晨 4 点规则） |
| 命中 | 同日直接返回已生成 `welcome`，不重复调 LLM |
| `force=true` | 重跑 sense/decide/speak |
| 存储 | 第一版可用进程内/简易表字段；后续可进 Redis 或 profile 快照 |

### 3.7 是否写入 GuideMessage

**首刀建议：欢迎语主要展示在欢迎卡，默认不写入会话历史。**

原因：避免「用户还没说话」就出现一条 assistant，与 `showQuickActions`、历史回放纠缠。  
若产品希望对话区也看到开场：可写入一条 assistant，但前端欢迎区仍以 `bootstrap.welcome` 为准，废弃静态 `GREETING` 双文案。

### 3.8 前端对接

```
initHome
  → requirePageAuth
  → Promise.all: fetchProfile / history / GET /guide/session / POST /guide/bootstrap
  → 欢迎卡文案 = bootstrap.welcome（失败则本地极简 fallback）
  → 可选：欢迎卡下「去xxx」按钮 ← next_action
```

删除或降级前端写死的「建议先从天赋测评开始…」三行，避免与后端抢话。

`showWelcomeCard`：无用户消息时显示欢迎区，文案仅来自 `bootstrap.welcome`（不再叠静态 GREETING）。

### 3.9 超时与降级

- LLM 调用建议超时 3～5s  
- 失败 / 未配置 → `source=template`，进页必有欢迎语  
- bootstrap 整接口失败 → 前端用极简本地句，不挡首页其它模块

### 3.10 首刀验收

| 场景 | 期望 |
|------|------|
| 未测评 | situation=`need_assessment`，欢迎导向天赋测试 |
| 已测评、今日未练 | `ready_to_train`，导向今日训练 |
| 今日已开始未完成 | `training_in_progress` |
| 今日已完成 | `training_done` |
| 间隔多日回访 | 文案或 situation 体现「欢迎回来」 |
| 同日二次进首页 | `source=cache`，不重复耗 LLM |
| 豆包不可用 | 仍有模板欢迎 |

### 3.12 项目结构（Agent 层）

与「快速互动 + 有工作能力」对应的目录（已搭骨架，A0 填实逻辑）：

```
backend/app/agents/guide/
├── persona.py       # 人设边界
├── context.py       # sense：GuideContext / build_guide_context
├── situations.py    # decide：resolve_situation + 欢迎模板
├── bootstrap.py     # 进页：run_bootstrap（sense→decide→speak）
├── runner.py        # 对话编排（A1/B）
├── memory.py        # 历史截断 / 开场缓存占位
└── tools/           # B：只读工具注册表
```

调用链：

```
api/guide.py  →  services/guide_service.py  →  agents/guide.bootstrap | runner
                      ↑ DB 会话持久化              ↑ 情境与决策 / LLM
```

开场 **不** 经 `tools/`（固定查库更快）；追问细节再经 tool-loop。

## 五、多 Agent 协作原则（2026-07-23）

当前产品级 Agent：**Guide（首页）** 与 **QA（答疑）**。排课仍为规则引擎，不在此列。

| 原则 | 说明 |
|------|------|
| 先各自完成 | Guide / QA 独立演进，互不 import |
| 薄交接 | 仅通过 `shared/handoff` 的 navigate（前端跳转）；禁止 `guide.runner` ↔ `qa.runner` |
| shared 范围 | 学段/天赋提示、handoff 白名单；不放排课/解题决策 |
| 何时上 Orchestrator | 同一对话框要自动切换导览↔讲题、或统一审计计费时再议 |
