# 前端更新说明：大宇改版壳页与业务双轨现状

> 更新日期：2026-09-10  
> 背景：`backend/dev` 合入 `feat(front): 接入大宇改版壳页，一比一展示 demo 前端`（`f832e02`）后，学生端主入口与底栏切换为「大宇」静态壳。  
> 目的：说明**当前前端真实结构**，避免把 Demo 壳误当成已接后端的正式业务页。  
> **本文只做现状记录与对照，不含大规模改造方案落地。**

---

## 1. 一句话结论

当前学生端是 **「大宇静态 Demo 壳 + 原 UniApp 业务页」双轨**：

| | 新壳（Demo） | 老业务页（真功能） |
|--|--------------|-------------------|
| 形态 | `iframe` / `web-view` 加载 `/static/dayu/html/*.html` | 原 Vue 页面 + `utils/api` |
| 后端 | **基本不调用**本系统 API | 引导 / 训练 / 答疑 / 测评等已接后端 |
| 入口 | 登录后默认落地；底栏五 Tab 全是壳 | 从壳内按钮「跳进」后才常用 |
| 关系 | 与老页 **互相跳转** | 老引导页底栏又指回壳，形成环 |

因此存在三类现象（均已观察到）：

1. **大量主题重叠**（同名能力两套实现）  
2. **新壳大量未接真实后端 API**  
3. **新老互跳**；主入口被壳占用，老首页/成长等被「盖住」感明显

## 2. 本次前端更新带了什么

### 2.1 新增 / 变更要点

- 应用 home 改为 `pages/dayu/home`（`pages.json` 中 `type: "home"`）  
- 登录、完善信息成功后默认 `reLaunch` → `/pages/dayu/home`  
- 底栏配置：`utils/mainTabs.js` 的 `MAIN_TABS` 指向壳路由  
- 通用容器：`components/dayu-frame`（H5 用 iframe，非 H5 用 web-view）

- 静态资源：`static/dayu/html/*`、`static/dayu/assets/*`、`static/dayu/style.css`  
- 壳路由页：`pages/dayu/home`、`training/dayu`、`qa/dayu`、`talent/hub`、`hub/*`  

### 2.2 同批后端相关（非 UI，一并记录）

- Redis 限流优先、会话 `last_active` 降频写库（`8089665`）——与壳页展示无直接关系。

## 3. 双轨架构示意

```text
学生登录成功
    ↓
【壳】pages/dayu/home  ← 静态 index.html（无本系统业务 API）
    │
    ├─ 底栏 → training/dayu | qa/dayu | hub/academy | hub/console（仍是壳）
    │
    ├─「开始对话 / 提问」→【老】pages/index?chat=1
    │                      （真 Guide Agent + API）
    │                         └─ app-tab-bar → 又回到壳 Tab
    │
    ├─ 修炼选时长确认 →【老】pages/training/index?dayu_minutes=…
    │                      （真训练打卡）
    │
    └─ 答疑深入入口 →【老】pages/qa/index?…
                       （真学科答疑）
                       ↑
                 qa/dayu 壳内聊天本身仍是 Demo
```

壳 ↔ 宿主通过 `window.parent.postMessage`：

- `type: 'dayu-nav'` + `path`：路由跳转  
- `type: 'dayu-train-confirm'` + `minutes`：进入老训练页并带时长  

部分路径在宿主侧会被 **改写**（例如把 `/pages/training/index` 改成 `/pages/training/dayu`），避免底栏误开老页。

## 4. 路由对照表（壳 vs 真功能）

| 用户感知 | 壳路由（Demo） | 静态页 | 真业务路由 | 是否接本系统 API |
|----------|----------------|--------|------------|------------------|
| 大宇 AI / 首页 | `/pages/dayu/home` | `index.html` | `/pages/index`（引导对话） | 壳：否；老页：是 |
| 今日修炼 | `/pages/training/dayu` | `train.html`（**已停用整页嵌入**） | `/pages/training/index` | **壳路由已接真 API（P0）**；旧页仍保留作对照/深链 |
| 学科答疑 | `/pages/qa/dayu` | `answer.html` | `/pages/qa/index` | 壳：否*；老页：是 |
| 天赋测评中心 | `/pages/talent/hub` | `test.html` | `/pages/talent/index`、`/pages/report/index` | 壳：否；老页：是 |
| 天赋学院 | `/pages/hub/academy` | `drama.html` | （无对等业务页） | 否 |
| 中央电脑 / 里程碑壳 | `/pages/hub/console` | `milestone.html` 等 | `/pages/growth/index`（老成长，底栏已不主推） | 壳：否；老成长：是 |
| 历史剧情 | `/pages/hub/story` | `history.html` | — | 否 |
| 天赋课程 | `/pages/hub/courses` | `courses.html` | — | 否 |
| 家长 | 壳内可链 `parent.html` → | — | `/pages/parent/index` | 老页：是 |
| 训练历史 | 壳映射可到 | — | `/pages/training/history` | 老页：是 |

\* `answer.html`：本地演示文案，或浏览器 **直连外部豆包**（用户自配 endpoint/key）；**不是**本仓库 `/api/qa` 会话链路。

## 5. 底栏与入口（为何像「老前端被盖住」）

### 5.1 当前主底栏（`MAIN_TABS`）

1. 大宇 AI → `/pages/dayu/home`  
2. 今日修炼 → `/pages/training/dayu`  
3. 学科答疑 → `/pages/qa/dayu`  
4. 天赋学院 → `/pages/hub/academy`  
5. 中央电脑 → `/pages/hub/console`  

全部为壳。顶区 chips：天赋测试 → `talent/hub`，历史剧情 / 天赋课程 → hub 壳。

### 5.2 登录落地

- 学生：`/pages/dayu/home`（不再默认进老 `/pages/index`）  
- 家长：仍 `/pages/parent/index`  

### 5.3 老页仍在，但降级为二级

仍保留且可用（需从壳跳入或深链）：

- `/pages/index` — 首页引导 Agent（真 API）  
- `/pages/training/index`、`history`  
- `/pages/qa/index`  
- `/pages/talent/index`、`/pages/report/index`  
- `/pages/growth/index`  
- 登录注册、管理端等  

**覆盖感来源：** 默认 home + 底栏被壳占据，老引导/老成长不再是第一触点。

## 6. 已知实现层问题（记录，非本次必改）

1. **双套导航**  
   - 静态 HTML 自带底栏  
   - 老 `/pages/index` 另挂 Vue `app-tab-bar`  
   视觉与路由逻辑两套并存。

2. **postMessage 监听可能重复**  
   - `dayu-frame` 内监听  
   - 部分壳页（如 `dayu/home`、`training/dayu`）再监听一遍  
   存在重复处理导航的风险。

3. **路径改写不一致**  
   - 有的场景故意把老训练/答疑路径改回 dayu 壳  
   - 有的场景（带 query 的答疑、时长确认）又进入老页  
   同一「答疑/训练」品牌下，用户有时在 Demo、有时在真功能。

4. **答疑壳直连模型**  
   - 与本系统鉴权、限流、会话落库、分科 Agent **脱节**  
   - 易造成「壳里能聊、正式链路另一套」的认知混乱。

## 7. 和「正式产品」的边界说明（给协作方）

| 问题 | 现状答案 |
|------|----------|
| 大宇改版是否等于前端重写完成？ | **否**。当前是 Demo 一比一嵌套展示。 |
| 壳上点按钮是否都已接后端？ | **否**。多数仅跳转或本地演示。 |
| 真训练 / 真引导 / 真答疑还在吗？ | **在**，在对应老 Vue 路由。 |
| 能否只验收壳页 UI？ | 可以验收视觉；**不能**用壳页单独验收业务闭环。 |
| 验收业务应打开哪些页？ | 引导：`/pages/index`；训练：`/pages/training/index`；答疑：`/pages/qa/index`；测评：`/pages/talent/index` 等。 |

## 8. 后续演进方向（仅方向，不落实施）

可选路径（需产品拍板，本文不实施）：

1. **壳只做皮**：壳内关键 CTA 一律进老业务页；逐步去掉 Demo 聊天/假数据。  
2. **壳重写成真 Vue**：按视觉重做页面并接 `utils/api`，淘汰静态 HTML。  
3. **双轨长期并存**：用文档/开关明确「展示环境 vs 业务环境」，避免混测。  

无论哪条，建议先统一：**对外演示口径**与**对内联调口径**，避免把 `qa/dayu` 当成已上线答疑 Agent。
