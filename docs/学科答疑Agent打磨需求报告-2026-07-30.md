# 学科答疑 Agent 打磨需求报告

> 日期：2026-07-30  
> 范围：`agents/qa` + `services/qa_*` + `api/qa.py` + `vue_fronted/src/pages/qa`  
> 立场：**另线打磨，不复制 Guide 全套；不做 Orchestrator**  
> 基线：Guide 主线 A0～C + P0/P1 + R5/R9/R10 已收口（2026-07-30）；QA 主功能可用，运行时与交接深度落后于 Guide

---

## 1. 背景与结论

### 1.1 背景

学科答疑是四大模块之一：分科人设、会话 CRUD、拍照 OCR、天赋注入、教练易错点、可选 RAG、SSE 流式均已落地。  
Guide 近两周完成了「多步查数 / 记忆 / 深交接 / 限流 / 评测 / 策略 / 受控写」等运行时升级；约定上 **QA 打磨为另线**，且 **Guide↔QA 互不 import runner**，靠 `shared/handoff` + 前端跳转联调。

当前落差主要在：

1. **交接断点** — Guide 已能带 `subject` / `hint` 跳答疑，QA 页不消费  
2. **记忆偏薄** — 近 10 轮原文 + 标题列表，无摘要/跨会话偏好  
3. **可运营质量** — 无限流、无 trace/回归标尺（相对 Guide R9/R13）  
4. **文档与实现漂移** — 功能模块文档偏规格稿；部分 API/闭环描述与代码不一致  
5. **语音** — 产品已明确去掉，不进本报告更新计划（代码开关可保持关闭，不作为 backlog）

### 1.2 一句话结论

QA 已是**能分科辅导、能看图答题的老师**，尚不是**能接住 Guide 交接、可持续记住学生、可限流可评测的答疑 Agent**。  
打磨目标：补齐用户可感知的断点与工程质量，**按需**吸收 Guide 已验证的轻量模式（记忆 / 限流 / 评测），**不**先行上 tool-loop、Generative UI、受控写或超级 Orchestrator。

### 1.3 与 Orchestrator 的边界（本报告明确不做）

| 做法 | 本报告态度 |
|------|------------|
| thin handoff（navigate + query，前端跳转） | ✅ 加深消费即可 |
| Guide.runner 调 QA.runner（或反向） | ❌ 禁止 |
| 统一入口超级编排器 | ❌ 暂不做（两边各自成熟后再议） |

## 3. 对照 Guide：哪些该学、哪些不学

Guide 已收口能力对 QA 的取舍：

| Guide 能力 | 对 QA | 说明 |
|------------|-------|------|
| bootstrap / proactive | 低优先 / 不做同构 | 答疑进页诉求是「问作业」，不是情境教练开场 |
| tool-loop / query normalize | 暂不做 | QA 真相源是题目+对话，不是打卡进度查数 |
| student_memory | **应学轻量版** | memory.py 已预留摘要扩展 |
| handoff.query 深交接 | **应收口消费** | Guide 已发，QA 未接 |
| ui_blocks / confirm 写 | 默认不做 | 无产品卡片/写画像诉求时勿造 |
| rate limit | **应对齐** | 防刷与成本 |
| eval / trace | **应对齐轻量版** | 分科 + 安全话术回归 |
| strategy | 可选 | 已有天赋注入；策略层非刚需 |
| R11/R12 多模态语音（Guide ⏸） | **QA 亦不做语音** | 拍图已上线；答疑 ASR/TTS 已明确移出本报告 |

## 4. 按项目分层：用户层 / 语义层 / 处理层

```text
用户层（答疑页体验与交接消费）
  pages/qa/index.vue · qaMedia.js · qaVoice.js · userApi.js
        │
语义层（分科、人设、教练、错频道）
  agents/qa/persona · router · prompt_builder · subjects/*
  agents/shared/talent · stage
  services/qa_coach · qa_rag_router
        │
处理层（OCR、RAG、LLM、落库、限流）
  services/qa_service · qa_image_store · qa_rag_client · qa_cache
  api/qa.py · api/voice.py（ASR/TTS 共享）
```

### 4.1 用户层要处理的断点

| 项 | 现状 | 打磨方向 | 建议档 |
|----|------|----------|--------|
| 深交接消费 | Guide 跳转带 query，QA 忽略 | 读 `from` / `subject` / `hint`：设学科 chip；hint 可预填输入或进首条系统提示 | P0 ✅ |
| mismatch UX | 后端返回 `suggested_subject` | 一键切学科 / 提示重发 | P0 ✅ |
| 「不会」三级引导 | 仅文档 | 话术渐进 + 复用学科 chip；不新造题型按钮 UI | P2 ✅ |

### 4.2 语义层要处理的断点

| 项 | 现状 | 打磨方向 | 建议档 |
|----|------|----------|--------|
| 教练元数据 | 只存 `mistake_pattern` | 文档改对齐代码，或补写 `coach_hint`（二选一，先对齐事实） | P0 ✅ |
| 记忆 | 10 轮截断 | 会话滚动摘要 + 可选「常错点/偏好学科」进 profile（轻量，对齐 Guide R2 思路） | P1 ✅ |
| 澄清 | 靠模型自由发挥 | 题干不清 / 无图无描述时强制先问一句（人设规则即可，不必上 grounding 协议） | P1 ✅ |
| 策略层 | 无独立 strategy | 按天赋/学段短策略注入 | P2 ✅ |

### 4.3 处理层要处理的断点

| 项 | 现状 | 打磨方向 | 建议档 |
|----|------|----------|--------|
| 限流 | chat 无 | 复用/对齐 Guide 的短窗 + 日配额思路（`check_guide_chat_limits` 模式） | P0 ✅ |
| 可观测 | 日志散 | 轻量 `qa_trace`（学科、是否 OCR/RAG、耗时、mismatch）+ debug 指标 | P1 ✅ |
| 评测 | 单测多、无场景回归集 | 增加 fixture：错频道、无图空问、安全拒答、RAG 触发边界 | P1 ✅ |
| 编排抽离 | 逻辑在 `qa_service` | 抽 `agents/qa/runner.py`；**仍禁止**调 Guide runner | P2 ✅ |
| `POST /api/qa/clear` | API 文档有、实现无 | 删文档或补实现（优先改文档，除非前端真需要） | P0 ✅ |

- 「不会」题型/拍照**新按钮矩阵 UI**（规格稿三级按钮；本轮用话术 + 现有 chip/拍照入口承接）  
- Orchestrator / Guide↔QA 互调 runner  
- 照搬 Guide tool-loop、Generative UI、受控写确认卡  
- 答疑运营审核后台  
- 拆除 QA 已有拍图能力
