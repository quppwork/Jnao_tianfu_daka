## 一、三类场景怎么区分

| 场景 | 期望 | 机制 |
|------|------|------|
| **开发**：关 `start.bat` 再开 | 要求重新登录，避免停在改崩前的页面 | `boot_id` 变化 + `force_relogin_on_boot`（开发默认开） |
| **生产**：用户关 App 再开 | **保持登录** | 不因 boot 清登录；session 在 DB + localStorage |
| **生产**：服务器升级 / 发新前端 | 可维护提示；仅不兼容时踢登录；新包提示刷新 | `JNAO_MAINTENANCE` / `JNAO_FORCE_LOGOUT` / `build_id` |

## 二、相关 API

### `GET /api/ping`

```json
{
  "ok": true,
  "boot_id": "…",
  "force_relogin_on_boot": true,
  "maintenance": false,
  "maintenance_message": "",
  "force_logout": false
}
```

- 维护中：`ok=false`，`maintenance=true`
- 启动脚本仍可用该接口探测进程是否起来（HTTP 200 即可）

### `GET /api/meta/version`

```json
{
  "version": "0.3.0",
  "build_id": "20260723-001",
  "boot_id": "…",
  "force_relogin_on_boot": false,
  "maintenance": false,
  "maintenance_message": "",
  "force_logout": false
}
```

前端 `appUpdate.js` 轮询此接口（约 5 分钟）：对比 `build_id`、展示维护遮罩、处理 `force_logout`。

## 三、环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `JNAO_ENV` | `development` | `production` 时关闭「进程重启强制重登」默认 |
| `JNAO_DEV_FORCE_RELOGIN` | 开发 `1` / 生产 `0` | 后端重启后清前端登录 |
| `JNAO_MAINTENANCE` | `0` | `1` = 维护模式 |
| `JNAO_MAINTENANCE_MSG` | 系统升级中… | 维护文案 |
| `JNAO_FORCE_LOGOUT` | `0` | `1` = 不兼容发版，清本地登录（**发完务必改回 0**） |
| `JNAO_BUILD_ID` | `dev` | 前端热更新比对；每次发前端包改一串 |
| `JNAO_APP_VERSION` | `0.3.0` | 展示用版本号 |
| `GUIDE_CHAT_RATE_LIMIT` | `1` | `0` = 关闭 Guide 对话限流 |
| `GUIDE_CHAT_QPS_MAX` | `10` | 每用户短窗内最大对话次数（chat+stream） |
| `GUIDE_CHAT_QPS_WINDOW_SEC` | `60` | 短窗秒数 |
| `GUIDE_CHAT_DAY_MAX` | `150` | 每用户自然日配额 |
| `GUIDE_PROACTIVE_ENABLED` | `1` | `0` = 关闭进页主动一句（掉队/连打/周简报） |
| `GUIDE_PROACTIVE_WEEKLY` | `1` | `0` = 关闭周简报类主动句 |
| `GUIDE_PROACTIVE_STREAK_MILESTONES` | `3,7,14,21,30` | 连打鼓励触发里程碑（天） |
| `GUIDE_STRATEGY_ENABLED` | `1` | `0` = 关闭 Guide 个性化策略注入（天赋/弱项/情境） |

代码：`backend/app/core/runtime.py`、`vue_fronted/src/utils/devBootAuth.js`、`appUpdate.js`。  
Guide 限流：`backend/app/core/rate_limit.py` → `check_guide_chat_limits`（单进程内存桶；多 worker 生产建议后续迁 Redis）。  
Guide 主动节奏：`backend/app/agents/guide/proactive.py`（频控写 `profile_json.guide_proactive`；也可设 `enabled:false` 按用户关闭）。  
Guide 策略层：`backend/app/agents/guide/strategy.py`（对话 / bootstrap 注入短策略块）。

## 四、推荐发版步骤（生产）

1. 设 `JNAO_MAINTENANCE=1`，重启后端（或滚动生效）→ 用户看到维护页  
2. 跑 DB 迁移 / 部署新后端  
3. **若本次改了登录协议**：临时 `JNAO_FORCE_LOGOUT=1`；否则保持 `0`  
4. 部署前端，改 `JNAO_BUILD_ID=日期-序号`  
5. 设 `JNAO_MAINTENANCE=0`，`JNAO_FORCE_LOGOUT=0`，确认 `/api/ping` 的 `ok=true`

日常小修复（API 兼容）：只需改 `BUILD_ID` + 部署，**不要**开 `FORCE_LOGOUT`。

## 六、训练/OSS 媒体播放优化

> 最后更新：2026-08-12  
> **生产现状（jnaosoft.cn）**：宝塔 CSP 已配对（`curl` 仅一行、含 `media-src` + OSS 域名），**保持该 Nginx 配置不动**。

### 播放链路（当前生产 — CSP + 直跳 OSS）

```
浏览器 → /api/training/items/.../stream（鉴权）
       → 302 → jnao-talent-ai.oss-cn-beijing.aliyuncs.com/...（签名 URL）
       → 200/206
```

视频流量走 OSS，不占 VPS 带宽；依赖宝塔 CSP 的 `media-src` 放行 OSS 域名。

### `.env.production`（与线上一致，勿乱改）

```env
SITE_DOMAIN=https://jnaosoft.cn
OSS_MEDIA_DIRECT_REDIRECT=1
OSS_MEDIA_SAME_ORIGIN_CACHE=0
```

- **`OSS_MEDIA_DIRECT_REDIRECT=1`**：鉴权后 302 到 OSS/CDN 签名 URL（必须开）。
- **`OSS_MEDIA_SAME_ORIGIN_CACHE=0`**：不改为同域 `/api/media/oss/`，与当前 CSP 直链方案一致。
- **禁止** `OSS_MEDIA_DIRECT_REDIRECT=0`；也无效：`DIRECT=0` + `SAME_ORIGIN=1`（同域缓存只在 `DIRECT=1` 时生效）。

### 备选：同域缓存（仅 CSP 未配好时临时用）

设 `OSS_MEDIA_SAME_ORIGIN_CACHE=1`（且 `DIRECT=1`）→ 302 到 `https://jnaosoft.cn/api/media/oss/…`，由前端容器 Nginx 磁盘缓存。  
**CSP 已配对后不必切换**，除非刻意要 VPS 本地缓存、减少重复 OSS 回源。

### OSS 控制台 CORS（直链模式）

Bucket `jnao-talent-ai` → 跨域：**来源** `https://jnaosoft.cn`，Methods GET/HEAD，Expose `Content-Range` 等。

### 宝塔 Nginx（CSP — 已上线，勿改）

- CSP 写在 **`location /` 反代块内**（见 `docker/baota-nginx.conf.example`）。
- 验证：`curl -sI https://jnaosoft.cn/ | grep -i content-security` → 一行，含 `media-src` 与 `oss-cn-beijing.aliyuncs.com`。
- 勿在 `server { }` 顶层重复 CSP；勿留 extension 目录第二条 CSP。

### 部署

```bash
cd /www/wwwroot/jnao_daka
git pull origin backend/dev
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

改 `.env.production` 后需 `--build` 重启 backend。**不必**为 CSP 方案单独重建 frontend（除非改了前端代码或 Nginx 模板）。

### 验证（强刷 / 无痕）

Network 应为：

1. `/api/training/items/.../stream` → **302**
2. `jnao-talent-ai.oss-cn-beijing.aliyuncs.com/...` → **200/206**
3. Console **无** `media-src blocked`

## 五、本地开发注意

- `start.bat` 停再起会换 `boot_id` → 浏览器刷新后需重新登录（可设 `JNAO_DEV_FORCE_RELOGIN=0` 关闭）  
- Vite 热更新、后端未重启：一般仍保持登录  
- 鉴权失败日志：`auth login fail` / `auth reject: invalid session`（见 `logs/app.log`）
