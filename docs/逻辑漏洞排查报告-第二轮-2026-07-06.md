## 🔴 CRITICAL

### 1. `duration_slot` 函数未定义 — 运行时报错崩溃

**文件:** [training_schedule_service.py:101](../backend/app/services/training_schedule_service.py#L101)

```python
def _plan_structure_invalid(plan, planned_minutes):
    slot_cfg = duration_slot(planned_minutes)  # ← NameError!
```

**`duration_slot` 在整个代码库中不存在。** 旧模块 (`training_block_builder`, `training_duration_pack` 等) 已被删除，只留下 `.pyc` 缓存文件。

**触发路径:**
```
POST /api/training/schedule
  → schedule_training_by_duration()
    → plan 已存在且有内容
      → _plan_structure_invalid(plan, planned_minutes)
        → duration_slot(planned_minutes)  ← 💥 NameError
```

**触发条件:** 训练方案已存在（非首次选时长），且 plan 有 items 时。

**影响:** 后端 500 崩溃。

**修复:** 实现 `duration_slot` 函数，或重写 `_plan_structure_invalid` 不依赖此函数。

## 🔴 HIGH

### 2. 选修占位项可重复添加（去重依赖 content_item_id）

**文件:** [training_service.py:1161-1169](../backend/app/services/training_service.py#L1161-L1169)

```python
# append_elective_item 的去重循环
for existing in plan.items:
    if existing.content_item_id:              # ← 占位项 id=None！
        ci = db.get(ContentItem, existing.content_item_id)
        ...
```

当 OSS 池中无匹配内容时，创建的占位项 `content_item_id=None`。下次 toggle 该技能时，占位项对去重循环不可见，**同一个 elective 技能被重复添加**，产生多条完全相同的占位项。

**修复:** 去重时也检查 `instructions` 中的 `skill` 字段，而非仅依赖 `content_item_id`。

### 3. 移除选修项后 TrainingRecord.item_id 变为悬空引用

**文件:** [training_service.py:1221-1256](../backend/app/services/training_service.py#L1221-L1256)

`remove_plan_item` 删除 `TrainingItem` 时不检查是否有 `TrainingRecord` 引用（`item_id` 无外键约束）。单独删除 item 的路径不调用 `_detach_checkin_records_from_plan`。

**影响:** 历史打卡记录的 `item_id` 指向不存在的行，数据完整性受损。

**修复:** 在 `remove_plan_item` 中增加 `UPDATE training_record SET item_id=NULL WHERE item_id=:id`。

### 4. unbind_child 不校验角色 — 可解绑任意用户

**文件:** [admin_service.py:351-353](../backend/app/services/admin_service.py#L351-L353)

```python
def unbind_child(db, admin_id, child_id):
    child = db.get(ChildUser, child_id)
    if not child or not auth_service.is_account_active(child):
        raise HTTPException(404, "孩子不存在")
    # ← 未检查 child.role != ROLE_STUDENT！
```

管理员可传入一个**家长或管理员**的 user_id 调用 `DELETE /api/admin/children/{id}/bind`，导致该用户的所有 `UserSession` 被删除、`session_token` 被清空，强制登出所有设备。

**修复:** 加 `or child.role != auth_service.ROLE_STUDENT` 到守卫条件。

### 5. unbind_child 不清除孩子身上的残留 parent 信息

**文件:** [admin_service.py:349-362](../backend/app/services/admin_service.py#L349-L362)

解绑后 `child.parent_phone` 仍保留原家长手机号，`profile_json["parentName"]` 仍保留原家长昵称。这些脏数据在管理后台详情中可见，直到重新绑定才会被覆盖。

**修复:** `unbind_child` 中置空 `child.parent_phone` 并清除 `profile_json` 中的 `parentName`。

## 🟡 MEDIUM

### 6. customize_plan_items 空 skills 仍锁定方案

**文件:** [training_service.py:1837-1915](../backend/app/services/training_service.py#L1837-L1915)

```python
mutable = _mutable_required_items(plan)   # 可能为空
if len(skills) != len(mutable):           # 0 != 0 → False，通过！
    raise TrainingError(...)
# 循环不执行（mutable 为空）
plan.plan_customized = 1                  # 但标记已编辑！
```

当所有必修项已完成时，客户端传空 `skills: []`，`len(skills) == len(mutable) == 0` 通过校验，循环体不执行，但 `plan_customized` 被置为 1，永久锁定方案无法再编辑。

**修复:** 在校验前检查 `mutable` 是否为空。

### 7. 必修项完成后再选时长 → duration_slot 崩溃（见 #1）触发条件明确

与 #1 相同根因，但触发场景更具体：用户完成所有必修项后重新选时长，`_plan_structure_invalid` 被调用 → `duration_slot` 崩溃。这是 #1 最常见的触发场景。

### 8. 老 Token 迁移绕过设备上限、内部 commit 污染外层事务

**文件:** [session_service.py:80-95](../backend/app/services/session_service.py#L80-L95)

```python
def _migrate_legacy_token(db, user, token):
    # 不调 _trim_sessions → 超限
    row = UserSession(...)
    db.add(row)
    db.commit()  # ← 内部 commit！污染外层事务
```

两个问题：
1. 直接插入 UserSession 不 trim，可能超出设备上限
2. 内部 `db.commit()` 会提交外层事务中的未完成工作

**修复:** 去掉内部 commit，调用 `_trim_sessions` 后再插入。

### 9. platform_config 绑定到第一个 admin — admin 被清理后读写异常

**文件:** [platform_config.py:19-28](../backend/app/services/platform_config.py#L19-L28)

```python
def _config_admin(db):
    return db.scalar(
        select(ChildUser)
        .where(role == ROLE_ADMIN, account_status == ACCOUNT_ACTIVE)
        .order_by(ChildUser.id).limit(1)
    )
```

平台配置存储在**第一个活跃管理员**的 `profile_json` 中。如果该管理员被直接 DB 操作归档（无 admin 删除 API 但也无保护），配置读取静默回退到默认值，写入抛出异常。

**修复:** 以非活跃 admin 兜底，或迁移到独立配置表。

### 10. 归档函数不提交 — 依赖调用者

**文件:** [admin_service.py:71,97](../backend/app/services/admin_service.py#L71-L97)

`_archive_student_account` 和 `_archive_parent_account` 本身不调用 `db.commit()`，依赖所有调用者（`delete_parent`、`delete_child`）在最后统一提交。如果未来有新调用点忘记 commit，所有归档操作静默回滚。

**修复:** 统一在 archive 函数中 commit，或不 commit 但在文档中明确标注约定。

### 11. elective toggle remove 路径子串匹配可能误判

**文件:** [training_service.py:650-652](../backend/app/services/training_service.py#L650-L652)

```python
if not target:
    if skill in (item.title or ""):  # 子串匹配！
        target = item
```

当 JSON 解析失败时，用 `skill in title` 做子串匹配。如果 `skill="感知力"`，title="感知力训练"，匹配成功。但 `skill="阅读"` 也会匹配 title="超脑阅读"。虽然后续 `remove_plan_item` 会因 `item_skips_checkin` 拒绝非选修项，但错误消息混乱。

### 13. `sync_pending_plan_content` 简单方案判定用 `not plan.planned_minutes`

**文件:** [training_service.py:310](../backend/app/services/training_service.py#L310)

```python
is_simple = len(plan.items) <= 1 and not plan.planned_minutes
```

`not plan.planned_minutes` 对 `None` 和 `0` 都为 True。若将时长设为 0（边界测试），可能误触发简单方案覆盖逻辑。应改为 `plan.planned_minutes is None`。
